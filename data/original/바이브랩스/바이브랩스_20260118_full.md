1. 문제 제기: 기존 방식의 한계
저자는 대용량 문서를 AI로 처리할 때 겪는 일반적인 문제들을 지적합니다:
RAG 방식: 문서를 청킹하고 벡터 DB에 저장하는 방식은 복잡한 아키텍처 구축이 필요합니다.

2. 핵심 아이디어: 인간의 스키밍 전략 모방
인간이 도서관이나 기술 보고서를 볼 때 전체를 읽지 않고 핵심만 빠르게 훑어보는 방식을 AI에게 가르치자는 것입니다. 이를 통해 전체를 읽지 않고도 문서의 핵심을 파악할 수 있습니다.
3. 기술적 구현 방법
저자가 제안하는 방법은 특별한 설치 없이 셸 명령어와 프롬프트만으로 구현됩니다:
사용 도구: head, tail, grep, sed, awk 등 CLI 유틸리티
출력 제한: 분석당 최대 100단어, 전체 작업에 2000단어 제한
금지 도구: 출력 제한이 없는 Read, Write, WebFetch 등은 사용 금지
4. 계층화된 샘플링 전략 (Stratified Sampling)
174페이지 NASA 보고서를 예시로 든 구체적 방법론:
문서를 6~8개 청크로 분할
시작(1~10%), 25%, 50%, 75%, 끝(마지막 10%) 지점에서 각각 샘플링
매 N번째 페이지를 체계적으로 읽음
총 20~30%만 읽고도 전체 문서의 정확한 개요 생성
5. 핵심 원칙: 투명성과 정직성
읽은 부분과 읽지 않은 부분을 명확히 표시
추측과 사실을 구분하여 라벨링
커버리지 퍼센티지 명시
전체 분석 요청 시 솔직하게 거부
6. 기대 효과
비용 대폭 절감: Claude Haiku 기준 100만 토큰당 약 1달러
처리 속도 향상: 전체를 읽지 않으므로 빠른 응답
분석 품질 향상: 정제된 관련 컨텍스트에 집중
이 방법론은 RAG 시스템 구축 없이도 대용량 문서를 효율적으로 분석할 수 있는 실용적인 접근법을 제시하며, 특히 완전한 문서 소비가 필수가 아닌 상황에서 매우 유용합니다.

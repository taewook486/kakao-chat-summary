[인플로] [오후 2:35] 그록한테 물어보니.. 이렇다네요.
원격 리눅스 서버에서 `claude --dangerously-skip-permissions -p "명령"` 같은 명령으로 Claude Code (또는 Claude Dev)를 돌리다가 SSH가 끊어지면 프로세스가 죽는 건 기본적인 SIGHUP 신호 때문이야.
이걸 해결하는 가장 좋은 방법은 **tmux**나 **screen** 같은 터미널 멀티플렉서를 사용하는 거야.
(둘 다 비슷한데, tmux가 더 현대적이고 기능이 많아서 요즘 대부분 tmux를 추천해.)
### 추천 방법: tmux 사용하기
1. 서버에 tmux가 설치되어 있는지 확인 (대부분의 리눅스에 기본 설치되어 있음)
```bash
tmux -V
```
없으면 설치: `sudo apt install tmux` (Ubuntu/Debian) 또는 `sudo yum install tmux` (CentOS/RHEL)
2. SSH로 서버에 접속한 후 새 tmux 세션 시작:
tmux new -s claude-session
(이름은 원하는 대로, 예: claude-session)
3. tmux 안에서 Claude 명령 실행:
claude --dangerously-skip-permissions -p "명령"
또는 Claude가 인터랙티브하게 동작하면 그냥 `claude`만 쳐도 되고.
4. 작업 중에 SSH가 끊어지더라도 프로세스가 살아 있게 하려면:
- **detach** (분리): Ctrl + b 를 누른 후 바로 d (Ctrl-b d) 누르기
→ tmux 세션이 백그라운드에서 계속 돌고 있어.
5. 다시 SSH로 접속했을 때:
tmux attach -t claude-session
또는 `tmux a` (가장 최근 세션 자동 attach)
그러면 이전에 돌던 Claude 작업이 그대로 살아 있는 상태로 돌아와서 확인/계속할 수 있어.
### 추가 팁
- 여러 세션 관리: `tmux ls`로 현재 세션 목록 확인
- 세션 이름 없이 시작하면 기본 세션으로: `tmux new`
- tmux 안에서 새 창/패널 만들기: Ctrl-b c (새 창), Ctrl-b % (세로 분할) 등
- 만약 Claude가 매우 오래 걸리는 작업을 한다면, tmux 안에서 `nohup`이나 `&`도 함께 쓰는 사람도 있지만 tmux만으로 충분해.
### 대안: screen (tmux 싫으면)
screen -S claude-screen
# Claude 명령 실행
# detach: Ctrl-a d
# 다시 attach: screen -r claude-screen
tmux가 더 편하고 추천돼!
이 방법으로 하면 SSH 끊겨도 작업이 죽지 않고, 재접속하면 바로 이어서 볼 수 있어.
필요하면 tmux config (~/.tmux.conf)에서 자동 복구 설정도 추가할 수 있음.

1. VS Code Remote
2. Zellij
[송기사/송명근] [오후 4:22] VS Code Remote - SSH와 Zellij는 원격 작업을 수행할 때 서로 다른 목적과 강점을 가집니다. 하나는 **완전한 개발 환경(IDE)**을, 다른 하나는 터미널 세션 관리를 담당합니다. 상세 비교와 사용법입니다.
1. VS Code Remote - SSH
서버에 있는 파일과 폴더를 내 컴퓨터에 있는 것처럼 편집할 수 있게 해주는 확장 프로그램입니다. 본격적인 코딩 및 개발 작업에 가장 적합합니다.
• 장점:
◦ 로컬과 동일한 경험: 로컬 PC의 테마, 플러그인, 단축키를 그대로 사용하면서 원격 서버의 리소스(CPU, RAM)를 활용합니다.
◦ 소스 코드 보안: 소스 코드를 로컬 컴퓨터로 다운로드할 필요 없이 원격 서버에서 직접 편집합니다.
◦ 강력한 기능: 코드 자동 완성(IntelliSense), 디버깅, 터미널 기능을 GUI 환경에서 쾌적하게 사용할 수 있습니다.
• 단점:
◦ 초기 설정: 원격 서버에 작은 'VS Code Server' 프로그램을 자동으로 설치하는 과정이 필요합니다.
◦ 네트워크 의존성: 네트워크가 끊기면 편집 흐름이 끊길 수 있습니다(자동 재연결 기능이 있지만 완벽하진 않습니다).
• 사용 방법:
1. VS Code의 확장(Extensions) 탭에서 Remote - SSH를 검색해 설치합니다.
2. F1 키(또는 Cmd+Shift+P)를 눌러 명령어 팔레트를 열고 Remote-SSH: Connect to Host...를 선택합니다.
3. user@ip-address (예: gh-runner@192.168.0.10)를 입력하여 접속합니다.
4. 접속 후 File > Open Folder로 서버의 프로젝트 폴더를 엽니다.
2. Zellij (젤리지)
tmux를 대체하는 현대적인 터미널 멀티플렉서입니다. SSH 접속이 끊겨도 실행 중인 작업(서버 실행, 긴 빌드 등)이 취소되지 않도록 세션을 유지해 줍니다.
◦ 세션 유지: 네트워크가 끊겨도 zellij attach 명령어로 작업을 그대로 복구할 수 있습니다.
◦ 낮은 진입장벽: 화면 하단에 단축키 가이드가 항상 표시되어, 복잡한 단축키를 외워야 하는 tmux보다 훨씬 배우기 쉽습니다.
◦ 화면 분할: 하나의 터미널 창을 여러 개(패널, 탭)로 쪼개서 동시에 여러 명령어를 실행할 수 있습니다.
◦ 터미널 전용: 텍스트 기반이므로, 마우스를 활용한 GUI 편집 기능은 없습니다.
1. 설치: 맥 미니 터미널에서 brew install zellij를 입력합니다.
2. 실행: 터미널에 zellij라고 치면 바로 실행됩니다.
3. 주요 단축키 (화면 하단에 표시됨):
▪ Ctrl + t 후 n: 새 탭 열기
▪ Ctrl + p 후 n: 화면 가로/세로 분할 (Pane)
▪ Ctrl + o 후 d: 세션 끊고 나가기 (Detach - 백그라운드에서 계속 실행됨)

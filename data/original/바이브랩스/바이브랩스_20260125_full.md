### 🌟 3줄 요약
이번 대화는 AI 코딩 도구 활용과 로컬 모델 실행에 대한 심층적인 경험 공유가 이루어졌습니다. 소크라테스 스킬 기반의 Claude Code 활용법, 안티그래비티와 GLM을 포함한 다중 AI 모델 조합 전략, 그리고 맥북 기반 개발 환경 구축에 대한 실질적인 조언이 오갔습니다. 오후에는 trae 해커톤 작품 평가와 함께 AI 기반 모션 비디오 생성 서비스가 기술적 완성도와 실용성 면에서 1등 후보로 선정되었습니다.
### ❓ Q&A 및 해결된 문제
**Q. 클로드 코드 맥스 사용량을 빨리 다 써버리면 어떻게 해야 하나요?**
A. GLM이나 Gemini Flash 같은 저렴한 모델로 대체하거나, 안티그래비티 울트라 오퍼스 무제한을 활용하는 방법이 있습니다. 클코드 100불 플랜은 삼일만에 토큰이 다 타버리는 경우가 많아서, 리팩토링 같은 작업은 GLM 같은 싼 모델로 처리하고 검증을 Claude에게 맡기는 전략이 효과적입니다. (답변자: 예레미야, Claudroid)
**Q. 맥에서 AI 개발 환경을 구축하려면 어떤 사양이 좋나요?**
A. M1pro 16GB로 시작할 수 있고, M2pro 64GB RAM이면 RAG 테스트도 가능합니다. 32GB RAM 이상의 맥미니(200만원대)나 48GB RAM 모델(270만원대)도 권장되며, 무이자 할부(18~23개월)를 활용하면 부담이 줄습니다. M5 맥북프로도 좋은 선택지입니다. (답변자: 바이브랩스 랩장, 예레미야)
**Q. RAG에서 임베딩 모델이 너무 느리거나 자원이 부족한데 해결법이 있나요?**
A. 로컬 임베딩은 M2pro 성능 한계가 있어서 오픈라우터 API의 Qwen 8B(1백만 토큰당 0.01달러)나 Voyage 모델(월 200만 토큰 무료)을 활용하는 것이 좋습니다. 64GB RAM 미니PC에 투자하는 것도 하나의 방법입니다. (답변자: Claudroid, 예레미야)
**Q. 소크라테스 스킬에서 "Toast me"를 입력하면 어떻게 되나요?**
A. 실제로는 "Roast me"가 정답이며, 소크라테스는 이를 진지하게 받아들여 5 Whys 기법으로 사용자의 숨겨진 욕망과 두려움을 끄집어냅니다. 장난으로 시작해도 왜 장난을 쳤는지 끝까지 파고들어갑니다. 매우 집요하고 뼈 때리는 평가를 받습니다. (답변자: 박기범, 바이브랩스 랩장)
**Q. 여러 AI 모델을 동시에 활용한 리서치 방법은?**
A. 랄프 루프를 활용하여 1) 원하는 질문대로 GitHub, 개발자 합의, 논문 등에서 검색하고 2) 문서화 시 중복을 제거하며 3) 다시 검색하는 과정을 50번 반복하여 중복이 제거된 완전한 단일 문서를 만드는 방법이 있습니다. 이때 GLM 4.7로 중복제거, Minimax로 빠른 응답, Perplexity로 심층 리서치를 조합하면 효율적입니다. (답변자: Claudroid, 예레미야)
### 💬 주요 토픽 & 논의
**AI 모델별 성능과 활용 전략**
대화에서는 다양한 AI 모델의 실제 사용 경험을 공유했습니다. Claude Opus는 50% 에러가 발생하고, 반중력(Gemini 3 Pro)과 GLM 4.7은 60% 에러, Minimax와 Grok Code Fast는 80% 에러가 나는 반면 ChatGPT Codex는 에러가 거의 없지만 느려서 사용하기 어렵습니다. 특히 Claude Code에서 소크라테스 스킬을 활용하면 코드 품질이 크게 향상되며, 소크라테스가 뼈대를 잡고 다른 모델들이 검증과 기능 추가를 담당하는 워크플로우가 효과적입니다.
안티그래비티(Anti-Gravity) 사용 중에는 토큰이 소진되어도 늦게 알려주는 경우가 있어 Gemini Pro로 전환해야 하는 상황이 발생합니다. Gemini Flash는 무제한이라 부담 없이 사용할 수 있고, GLM은 월 100억 토큰을 사용 가능하므로 마음껏 활용하라는 조언이 있었습니다.
**리팩토링과 기술 부채 관리**
리팩토링 시 토큰 소모가 크기 때문에 GLM 같은 저렴한 모델로 기본 작업을 처리하고, Claude에게 검증을 맡기는 전략이 권장됩니다. "기술부채 있니?"라는 간단한 질문으로 프로젝트의 기술 부채를 확인하는 팁이 공유되었으며, 이 방법은 특히 AI 코드 품질 검증에 효과적입니다.
코드 분석 도구로는 Bandit(보안), Ruff(린팅), Radon(복잡도), Vulture(미사용 코드), mypy(타입 분석), pytest(테스트), coverage(커버리지)가 언급되었고, 이를 자동화 스크립트로 통합하여 분석 속도를 2~3배 향상시킬 수 있다고 합니다.
**RAG(검색 증강 생성) 구축 경험**
DGX Spark에서 GPT-OSS-120B를 테스트했으나 코딩 작업에서 context length 에러가 발생하여 Qwen Corder로 바꿨지만 퀄리티가 떨어졌습니다. RAG 테스트에는 64GB RAM 미니PC가 적합하며, Ollama가 잘 돌아갑니다. Voyage 모델은 컨텍스트 3만 토큰에 월 200만 토큰 무료로 매우 저렴하고, 오픈라우터 API의 Qwen 8B 임베딩도 1백만 토큰당 0.01달러로 경제적입니다.
로컬 임베딩은 M2pro 성능 한계로 인해 API 방식으로 전환하는 추세이며, GLM 4.7보다 Minimax가 5배 정도 빨라서 중복제거 작업에 적합합니다.
**해커톤 작품 평가: 모션 비디오 생성 서비스**
trae 해커톤 작품 중 마크다운을 완성도 높은 모션그래픽 비디오로 자동 생성하는 서비스가 1등 후보로 선정되었습니다. Trinity Score(眞善美) 기준으로 기술력 9.5점, 유용성 9.0점, 아름다움 9.2점으로 종합 9.23점을 받았습니다. Remotion + Next.js + Claude + Gemini + Kling 등 최신 멀티 AI 파이프라인을 활용하여 마케터와 크리에이터가 실제로 쓰고 싶어할 실용성을 갖추고 있습니다.
다른 후보로는 LoveDAQ - 다이어리(감성적, 독창적 아이디어, 8.7~8.9점), 나 떠날래(여행 시뮬레이션, 8.4~8.6점), ATC(에이전트 오케스트레이션, 8.2~8.5점), WorkLog AI(생산성 도구, 7.8~8.2점)가 있었습니다.
**맥 개발 환경과 하드웨어 투자**
M1pro 16GB 512GB 모델을 70만원에 중고로 구매한 사례가 있었고, M2pro 64GB로 RAG 테스트가 가능하다는 평이 있었습니다. 맥은 Windows 환경에서 VSCode 설정에 6시간 걸리는 것과 비교하면 30분 만에 설정이 완료되는 편의성이 장점입니다. M5 맥북프로는 하드웨어 성능이 크게 향상되어 AI 개발에 유리하며, 128GB RAM도 고려할 만하다는 의견이 있었습니다.
**책과 영상 학습에 대한 논의**
책은 구조적으로 사고하며 접근할 수 있어 기초를 탄탄히 잡기 좋지만, 발전 속도가 빠른 분야는 출판이 기술 발전을 따라잡기 어렵습니다. MZ세대는 영상으로 빠르게 습득하지만 빠르게 잊는 경향이 있어, 책으로 기초를 잡고 커뮤니티나 SNS에서 최신 지식을 따라가는 것이 효율적이라는 분석이 있었습니다.
### 💡 꿀팁 및 도구 추천
**AI 모델 조합 및 활용 팁**
소크라테스 스킬 기반의 Claude Code는 코드 품질이 뛰어나고, 복잡한 태스크는 여러 개로 쪼개서 처리하는 것이 핵심입니다. 맥에서 클로드 코드 사용 시 환경변수 설정으로 모델별로 아이디를 다르게 하여 클코드 클로드 프로페셔널을 활용할 수 있습니다. 반중력이 중2병 걸린 것처럼 자기 말만 안 들을 때는 opsu 4.5로 잠깐切换해보라는 조언이 있었습니다.
GLM은 한달 100억 토큰을 사용할 수 있어 마음껏 쓰되, 코딩 작업에는 적합하지 않고 응답 속도가 빠른 Minimax는 리서치와 중복제거에 활용하는 것이 좋습니다. ChatGPT Plus는 1분에 3개 이상 질문이 불가능하므로 주의가 필요합니다.
**개발 워크플로우 최적화**
소크라테스로 뼈대 만들기 → /deep-research 스킬로 perplexity로 리서치 후 상호 실행 및 기능 추가 검증 → 사용자 플로우 검증 → 문서 간 무결성 검증을 반복하면 빌드 퀄리티가 향상됩니다. 코드 분석 시 "기술부채 있니?"라고 물어보면 기술 부채를 확인할 수 있습니다.
맥 초기 설정 시 바이브랩스 랩장의 socrates 기반 가이드를 따르면 하루 만에 화합물 제조 계산기를 만들 수 있는 실력자도 나왔습니다.

[예레미야] [오후 2:40] # LightOn OCR-2 소개 및 분석
## 1. 개요
LightOn OCR-2는 프랑스 AI 회사 LightOn에서 개발한 오픈소스 비전-언어 모델로, 1B 파라미터 규모의 엔드-투-엔드(end-to-end) OCR(Optical Character Recognition) 솔루션입니다. 이 모델은 PDF, 스캔 문서, 이미지를 자연스러운 순서의 텍스트로 변환하며, 기업 문서 인텔리전스에 특화되어 있습니다. OlmOCR 벤치마크에서 SOTA(State-of-the-Art) 성능을 달성하며, 더 큰 모델(예: 9배 규모)을 능가하는 효율성을 자랑합니다. 모델은 Hugging Face를 통해 공개되어 있으며, 기본 OCR 버전과 bounding box(bbox) 변형, fine-tuning용 베이스 체크포인트가 포함됩니다.
### 1.1. 주요 특징
- 파라미터 수: 1B (LightOnOCR-2-1B).
- 다국어 지원: 여러 언어의 문서 처리 가능.
- 배포 방식: 온-프레미스(on-premise) 적합, 민감 데이터 보호.
- 이전 버전(LightOnOCR-1B) 대비 데이터 믹스 확대와 교사 모델 업그레이드로 성능 향상.
## 2. 장단점
LightOn OCR-2는 가벼운 모델임에도 높은 성능을 발휘하지만, 특정 환경에서 제한이 있을 수 있습니다. 아래는 주요 장단점을 정리한 내용입니다.
### 2.1. 장점
- **높은 성능과 정확도**: OlmOCR 벤치마크에서 83.2 점수를 기록하며, DeepSeek OCR 등 경쟁 모델을 능가. 복잡한 레이아웃, 테이블, 구조화된 문서를 잘 처리.
- **효율성과 속도**: 1B 파라미터로 가볍고, H100 GPU에서 빠른 추론(예: PaddleOCR보다 2.7배 빠름). 엔드-투-엔드 아키텍처로 별도 OCR 파이프라인 불필요.
- **배포 용이성**: 온-프레미스 배포 가능, vLLM 통합으로 생산 환경 적합. fine-tuning 지원으로 도메인 적응 쉬움.
- **오픈소스**: MIT 라이선스 하에 공개, 커뮤니티 활용 가능.
### 2.2. 단점
- **리소스 요구**: 소규모 모델이지만, fine-tuning이나 대규모 문서 처리 시 GPU(예: H100) 필요. 일부 사용자는 "Huge Requirements"로 지적.
- **특정 도메인 한계**: 기본 모델은 일반 문서에 최적화되어 있으나, 고도로 전문화된 분야(예: 고대 언어)에서 추가 fine-tuning 필요. 초기 훈련 후 성능 향상이 관찰되지만, 초기 상태에서 약할 수 있음.
- **비교적 최근 릴리스**: 2026년 1월 릴리스로 장기 안정성 데이터 부족. 더 큰 모델(예: 3B 이상) 대비 복잡한 차트 재렌더링에서 약간 뒤처질 수 있음.
## 3. 설치 방법
LightOn OCR-2는 Python 기반으로 쉽게 설치할 수 있습니다. Hugging Face Transformers 라이브러리를 활용하며, 아래 단계로 진행합니다.
### 3.1. 환경 설정
- Python 3.8 이상 설치.
- 필요한 라이브러리 설치: `pip install transformers torch pillow` (Torch는 GPU 지원 버전 권장).
### 3.2. 모델 다운로드
- Hugging Face에서 모델 로드:
```python
from transformers import AutoProcessor, PaliGemmaForConditionalGeneration
model_id = "lightonai/LightOnOCR-2-1B"
model = PaliGemmaForConditionalGeneration.from_pretrained(model_id).eval()
processor = AutoProcessor.from_pretrained(model_id)
```
- bbox 변형 모델: "lightonai/LightOnOCR-2-1B-bbox".
- 로컬 설치: GitHub나 Hugging Face에서 직접 클론 가능. vLLM 통합으로 대규모 배포 시 사용.
### 3.3. 추가 팁
- GPU 사용 시 CUDA 설치 확인. fine-tuning용 Colab 노트북 제공됨.
## 4. 수행 방법
모델을 로드한 후 문서 이미지를 입력으로 텍스트를 추출합니다. 아래는 기본 예시입니다.
### 4.1. 기본 OCR 수행
- 이미지 준비: Pillow 라이브러리로 이미지 로드.
- 코드 예시:
import requests
from PIL import Image
# 이미지 로드 (URL 또는 로컬 파일)
image = Image.open(requests.get("https://example.com/document.jpg", stream=True).raw)
# 프롬프트 설정
prompt = "ocr"  # 기본 OCR 모드
# 입력 처리
model_inputs = processor(text=prompt, images=image, return_tensors="pt")
input_len = model_inputs["input_ids"].shape[-1]
# 생성
with torch.inference_mode():
generation = model.generate(**model_inputs, max_new_tokens=1000, do_sample=False)
generation = generation[0][input_len:]
decoded = processor.decode(generation, skip_special_tokens=True)
print(decoded)
- 출력: 문서의 텍스트를 Markdown 형식으로 구조화.
### 4.2. bbox 모드 수행
- 프롬프트: "ocr with bbox"로 이미지 내 요소 위치 추출.
- fine-tuning: 제공된 Colab 노트북으로 데이터셋 적용.
### 4.3. 성능 최적화
- 배치 처리: vLLM으로 여러 문서 동시 처리. 속도: ~2,500 토큰/s (A100 GPU).

### Figma 사용 방법 상세 가이드 (초보자向け)
Figma는 웹 기반의 무료 UI/UX 디자인 툴로, 실시간 협업과 프로토타이핑이 강점입니다. 2026년 기준으로 **한국어 인터페이스**를 공식 지원하니 편리하게 사용할 수 있어요. 아래에 계정 생성부터 기본 기능, 실무 활용까지 단계별로 자세히 설명하겠습니다.
#### 1. Figma 시작하기: 계정 만들기와 한국어 설정
1. 브라우저로 [www.figma.com](https://www.figma.com)에 접속하세요.
2. **Sign up for free** (무료 가입) 버튼을 클릭합니다. Google, Apple, 이메일 등으로 가입 가능합니다. (이미 계정이 있으면 Log in)
3. 가입 후 대시보드(홈 화면)가 나타납니다. 여기서 최근 파일, 드래프트, 팀 프로젝트 등을 확인할 수 있습니다.
4. **한국어 인터페이스 설정** (2025년부터 지원):
- 오른쪽 상단 프로필 아이콘 클릭 → Settings → Language → 한국어 선택 → Save.
- 이제 메뉴와 도구 이름이 한국어로 바뀝니다. (예: Move Tool → 이동 도구)
#### 2. 새 파일 만들기와 기본 인터페이스 이해
1. 대시보드에서 오른쪽 상단 **새 디자인 파일** (또는 New design file) 버튼 클릭.
2. 빈 캔버스가 열립니다.
**Figma 인터페이스 주요 영역** (한국어 모드 기준):
- **왼쪽 툴바**: 주요 도구
- 이동 도구 (V): 객체 선택/이동
- 프레임 도구 (F): 모바일/웹 화면 아트보드 생성
- 도형 도구 (R: 사각형, O: 원, L: 선 등)
- 펜 도구 (P): 자유로운 형태 그리기
- 텍스트 도구 (T)
- 손 도구 (H): 캔버스 이동
- **상단 메뉴 바**: 레이어 옵션, 정렬, 오토레이아웃 등
- **오른쪽 사이드바**:
- 디자인 탭: 색상, 효과, 스타일 설정
- 프로토타입 탭: 인터랙션 연결
- 검사 탭: 개발자 핸드오버 (코드 확인)
- **왼쪽 레이어 패널**: 모든 객체 계층 구조 (페이지 → 프레임 → 그룹 → 개별 객체)
- **중앙 캔버스**: 실제 디자인 작업 공간 (무한 확대/축소 가능, Ctrl + 마우스 휠)
#### 3. 기본 디자인 작업 절차
**단계 1: 프레임(Frame) 만들기** (아트보드 역할, 필수!)
- 툴바에서 프레임 도구 (F) 선택.
- 캔버스에 드래그해서 그리거나, 오른쪽 사이드바에서 프리셋(iPhone, Desktop 등) 선택.
- 프레임 안에 모든 요소를 넣습니다. (프레임 밖은 정리용으로 사용)
**단계 2: 도형과 텍스트 추가**
- 도형 도구로 사각형/원 그리기 → 오른쪽 디자인 패널에서 Fill(채우기 색상), Stroke(테두리), Corner Radius(모서리 둥글기) 조정.
- 텍스트 도구 (T) 클릭 → 캔버스 클릭 → 텍스트 입력.
- 폰트는 Google Fonts/Noto Sans Korean 등 한국어 잘 지원.
**단계 3: 객체 정렬 및 그룹화**
- 여러 객체 선택 (Shift 클릭 또는 드래그) → 상단 바에서 Align(정렬), Distribute(간격 균등) 사용.
- 그룹화: Ctrl + G (그룹 해제: Ctrl + Shift + G)
**단계 4: 오토레이아웃(Auto Layout) 적용** (반응형 디자인 핵심!)
- 객체 여러 개 선택 → 오른쪽 상단 **오토레이아웃 추가** 버튼 (또는 Shift + A).
- 패딩, 간격, 방향(가로/세로), 정렬 설정 가능.
- 버튼이나 카드 리스트 만들 때 필수 – 크기 변경 시 자동 조정됩니다.
#### 4. 중급 기능: 컴포넌트(Component)와 스타일(Style)
**컴포넌트 만들기** (재사용 가능한 요소)
1. 버튼 같은 객체 그룹 선택 → 오른쪽 디자인 패널에서 **컴포넌트 만들기** (다이아몬드 아이콘).
2. 메인 컴포넌트가 생성되면 인스턴스(Ctrl + Alt + K로 자산 패널에서 끌어옴)로 복사 가능.
3. 메인 수정 시 모든 인스턴스 자동 반영 → Variants(변형)로 Hover/Active 상태 만들기.
**스타일 적용**
- 색상/텍스트/효과를 스타일로 저장 → 팀 전체 일관성 유지.
#### 5. 프로토타이핑(Prototype) 만들기
1. 오른쪽 탭을 **프로토타입**으로 전환.
2. 시작 프레임 지정 (Device 프리셋으로 모바일 미리보기).
3. 객체 드래그해서 다른 프레임으로 연결 → Interaction 설정 (On Click → Navigate to, After Delay 등).
4. 애니메이션: Smart Animate, Ease In Out 등 선택.
5. 상단 **재생** 버튼으로 미리보기 → 공유 링크로 다른 사람과 테스트.
#### 6. 협업과 고급 팁
- 실시간 협업: 파일 공유 → 다른 사람이 동시에 편집 가능 (커서 색상으로 구분).
- 댓글: Ctrl + Alt + C로 특정 위치에 댓글 달기.
- 플러그인: Community에서 검색 (예: Unsplash 사진 삽입, Iconify 아이콘).
- Dev Mode: 개발자 핸드오버용 (CSS 코드 자동 추출).

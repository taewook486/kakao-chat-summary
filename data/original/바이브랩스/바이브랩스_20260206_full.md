## mem0가 하는 일 (감으로 이해하기)
보통 LLM은 “지금 대화창” 밖의 내용을 잘 잊어버리죠. mem0는 그걸 이렇게 바꿉니다:
1. **Auto-Capture (자동 저장)**
대화가 끝날 때(혹은 매 턴), “이건 나중에 꼭 필요하겠다” 싶은 것만 뽑아서 메모리로 저장합니다. ([Mem0][2])
2. **Store (보관)**
저장된 기억은 벡터 검색(의미 검색) 기반으로 쌓이고, 환경에 따라 더 구조적인 방식도 씁니다(예: 관계 중심). ([Mem0][3])
3. **Auto-Recall (자동 불러오기)**
사용자가 새 메시지를 보내면, 그 메시지와 관련 있는 기억만 찾아서 **프롬프트 컨텍스트에 “주입”**해줍니다. 그래서 봇이 “아, 이 사람은 전에 X를 좋아한다고 했지” 같은 흐름을 자연스럽게 이어갑니다. ([Mem0][2])
→ 사용자가 “같은 말 또 하기”를 덜 하게 되니까, 체감상 **봇 IQ가 확 올라간 느낌**이 납니다. ([Mem0][3])
## “OpenClaw 봇이 mem0로 히트쳤다” 느낌의 정체
mem0 문서에 **OpenClaw용 플러그인**이 따로 있고, 거기 핵심이 딱 이거예요:
* **Auto-Recall**: 답변 전에 관련 기억을 자동 주입
* **Auto-Capture**: 답변 후에 “저장할 것”만 자동 선별/저장
* * 필요하면 메모리를 직접 다루는 툴들도 제공 ([Mem0][2])
즉, OpenClaw로 만든 봇이 “세션마다 기억이 초기화되는 문제”를 mem0로 해결하면, 사용자는 **연속성/개인화**를 바로 느끼니까 “와, 얘 진짜 나를 아네?”가 됩니다. ([Mem0][2])
(참고로 설치 커맨드는 문서에 이렇게 나옵니다.) ([Mem0][2])
```bash
openclaw plugins install @mem0/openclaw-mem0
```
## RAG(그냥 대화 저장/검색)랑 뭐가 달라요?
“채팅 로그를 통째로 저장하고 검색”은 보통 **노이즈가 많고**, “뭘 기억해야 하는지”를 개발자가 계속 손봐야 합니다.
mem0는 기본 철학이 **“기억의 생애주기(추출→정리→검색→주입)를 자동화”** 쪽이라, 운영/품질이 한 단계 쉬워지는 포지션입니다. ([Amazon Web Services, Inc.][4])
추가로 검색 품질을 위해 **reranker(재정렬)로 한 번 더 점수 매겨서** “진짜 관련 있는 기억”을 위로 올리는 기능도 문서에 있습니다. ([Mem0][5])

qmd란?
Shopify 창업자 Tobias Lütke가 만든 로컬 하이브리드 검색 엔진입니다. 마크다운 문서, 회의록, 지식 베이스를 인덱싱해서 완전히 로컬에서 검색할 수 있게 해줍니다. 클라우드 의존성 제로, 프라이버시 퍼스트.
핵심은 3단계 하이브리드 검색 파이프라인입니다. BM25(키워드) + 벡터(시맨틱) + LLM 리랭킹을 결합해서 정밀한 검색 결과를 돌려줍니다. 그리고 결정적으로 MCP 서버를 내장하고 있어서 Claude 등 AI 에이전트와 바로 통합됩니다.
왕국 적합도 분석
1. 문서 검색 문제 해결 — 왕국에 297+ 문서, 2,800줄 Evolution Log, 43 티켓, 348 스크립트가 있는데, 현재 이걸 효과적으로 검색할 통합 시스템이 없습니다. qmd가 이 갭을 정확히 메웁니다.
2. MCP 네이티브 — 왕국은 이미 .mcp.json으로 MCP Docker Gateway와 afo-ultimate-mcp를 운용 중입니다. qmd의 MCP 서버를 추가하면 모든 Chancellor(자룡, 제미나이, 오호 등)가 문서 검색을 도구로 쓸 수 있습니다.
3. 토큰 절감 95%+ — 현재 SSOT 문서를 컨텍스트에 통째로 넣는 방식 대신, qmd로 관련 청크만 검색해서 넣으면 토큰 비용이 극적으로 줄어듭니다. /ssot 스킬의 진화 경로가 됩니다.
4. 十一臟腑 매핑 — 肺(Lungs, Vector Store)에 자연스럽게 편입됩니다. 현재 LanceDB/Qdrant가 담당하는 영역에 마크다운 전용 검색 레이어를 추가하는 셈입니다.
5. 로컬 우선 — 왕국의 start_kingdom_v2.sh가 Docker 없이 로컬 실행을 지향하는 철학과 완전히 일치합니다.

**아무도 말하지 않는 문제**
Claude Code는 놀라운 도구입니다. 하지만 숨겨진 단점이 있습니다: 컨텍스트 수집은 비용이 많이 듭니다. "인증 미들웨어가 어디 있나요?"라고 물으면 실제로 뒤에서 이런 일이 벌어집니다:

2. Claude가 Grep을 실행해 키워드를 검색합니다 — 토큰 추가 소모
3. Claude가 올바른 파일을 찾기 위해 3~4개 파일을 통째로 읽음 — 토큰 추가 소모
4. 클로드가 마침내 필요한 실제 코드를 읽음 — 유일하게 유용한 부분
1~3단계는 순수한 낭비입니다. 클로드가  정보를 *찾는*데 비용을 지불하는 것이지 ,  정보를*사용하는* 데 쓰는 게  아닙니다 . 중간 규모 코드베이스에서는 토큰 예산의 80~90%가 실제 코딩이 아닌 탐색에 소모됩니다.
저는 로컬에서 20개 이상의 프로젝트를 관리합니다. 토큰 사용량이 미친 수준이었죠. 끊임없이 한도에 부딪혔고, 응답은 느렸으며, 컨텍스트 윈도우의 절반은 클로드가 필요조차 없는 코드로 채워졌습니다.
그러다 qmd를 발견했고, 모든 것이 바뀌었습니다.
**qmd란 무엇인가요?**
qmd는 AI 에이전트 워크플로우를 위해 특별히 제작된 로컬 문서 인덱서입니다. 프로젝트 디렉터리를 지정하면 모든 것을 인덱싱하고, 그 인덱스를 Claude Code가
이 직접 쿼리할 수 있는 MCP 서버로 노출합니다.
클로드가 모든 파일을 수동으로 읽게 하는 대신, 코드베이스 전용 검색 엔진을 제공하는 것이라고 생각하세요.
다음과 같은 대신:
*"당신이 묻는 내용을 찾으려면 모든 파일을 읽어봐야겠네요"*
이제 Claude는 이렇게 합니다:
*"인덱스를 검색해서 10줄 분량의 코드 조각을 가져온 다음 바로 작업에 착수할게"*
**실제 수치**
저는 일반적인 작업 흐름에서 토큰 사용량을 추적했습니다. 결과는 충격적이었습니다.

## 규칙: 파일 읽기 전에 항상 qmd 사용
파일 읽기나 디렉터리 탐색 전에 항상 qmd를 사용하여 로컬 프로젝트 내 정보를 검색하십시오.
사용 가능한 도구:
- `qmd search “query”` — 빠른 키워드 검색 (BM25)
- `qmd query “쿼리”` — 재정렬이 포함된 하이브리드 검색 (최고 품질)
- `qmd vsearch “쿼리”` — 의미 벡터 검색
- `qmd get ` — 특정 문서 검색
빠른 조회에는 qmd search를, 복잡한 질문에는 qmd query를 사용하십시오.
qmd가 충분한 결과를 반환하지 않을 때만 Read/Glob을 사용하십시오.
이 설정이 적용되면 Claude는 항상 먼저 인덱스를 검색합니다.
인덱스를 통해 필요한 내용을 찾을 수 없을 때만 전체 파일 읽기로 전환합니다.
— -
**의 세 가지검색모드설명**: **search**, **,**
qmd는 세 가지 검색 방식을 제공하며 각각 다른 장단점이 있습니다:
**search** — BM25 키워드 검색. 가장 빠른 옵션입니다. 정확히 찾는 용어를 알고 있을 때 효과적입니다. "auth middleware", "checkout handler", "database
연결". 80%의 경우 이 방법을 사용하세요.
**vsearch** — 벡터 유사도 검색. 정확한 키워드 일치 없이도 개념적으로 관련된 콘텐츠를 찾기 위해 임베딩을 사용합니다. "앱이 오류를 어떻게 처리하나요?"라고 물으면
FallbackUI.tsx로 명명된 오류 경계 컴포넌트도 찾아냅니다. 탐색적 질문에 탁월합니다.
**query** — 쿼리 확장 및 LLM 재정렬을 결합한 하이브리드 검색. 두 방식을 통합하고 결과를 재정렬하여 정확도를 극대화합니다. 속도는 느리지만 품질이 가장 우수합니다.
가장 관련성 높은 결과가 필요한 복잡한 질문에 사용하세요.
**왜** **이지** **이고** **이 작동하는가**
핵심 통찰은 간단합니다: Claude Code의 기본 도구는 범용으로 설계되었습니다. Glob은 파일을 찾고, Grep은 콘텐츠를 검색하며, Read는 파일 내용을 읽습니다.
작동하지만, 정교하지 못한 도구입니다.
qmd는 Claude에게 순위별 결과, 스니펫, 정확한 파일 위치를 포함한 사전 구축된 인덱스를 제공합니다. 코드베이스를 선형적으로 스캔하는 대신 직접 조회하는 방식입니다.
도서관에서 모든 책장을 직접 찾아다니며 책을 찾는 것과 카탈로그에서 검색하는 것의 차이입니다.
**가** **를** **나에게바꾼점**
- 모든 세션에서 토큰 사용량이 급격히 감소했습니다
- 응답 속도 향상 (처리해야 할 컨텍스트 감소)
- 20개 이상의 프로젝트를 컨텍스트 혼란 없이 작업할 수 있음
- Claude가 전체 파일의 잡음 대신 타깃팅된 관련 코드를 인식하므로 오류가 줄었습니다
- 속도 제한에 걸리는 빈도가 훨씬 줄었습니다
**의핵심**
중요한 코드베이스에서 Claude Code를 사용하면서 인덱싱하지 않는다면, 매번 상호작용할 때마다 토큰 세금을 내는 셈입니다. qmd는 그 세금을 없앱니다.

### 핵심 아이디어
- Claude Code는 질문할 때마다 `glob → grep → 여러 파일 Read`를 하면서 실제 필요한 코드보다 10배 가까이 많은 코드를 읽어서 토큰을 쓴다는 문제를 지적합니다. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- 글쓴이는 여러 프로젝트를 관리하다가 qmd를 도입했고, 일반적인 작업에서 평균 약 92% 토큰을 절약했다고 주장합니다. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
### qmd가 무엇을 하는지
- qmd는 로컬 문서/코드 인덱서로, 프로젝트 디렉터리를 인덱싱하고 이를 Claude Code에서 MCP 서버로 쿼리할 수 있게 해줍니다. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- 이로 인해 Claude는 파일 전체를 읽기 전에 `search/query/vsearch`로 짧은 스니펫만 찾아서 바로 필요한 부분만 읽도록 바뀝니다. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
### 토큰 절감 예시
각 시나리오에서 “기존 Claude Code만 사용” vs “qmd 사용”을 비교합니다. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- 인증 로직 찾기: 기존 약 2,700토큰 → qmd 사용 시 약 250토큰, 91% 절감. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- 체크아웃 버그 수정: 기존 약 3,950토큰 → qmd 사용 시 약 400토큰, 90% 절감. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- DB 스키마 파악: 기존 약 6,050토큰 → qmd 사용 시 약 400토큰, 93% 절감. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
### 설치 및 설정 방법 (요약)
1. Bun 설치 후 `bun install -g https://github.com/tobi/qmd`로 qmd 설치. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
2. 프로젝트별 인덱스 생성:
- `qmd collection add ./my-project —name myproject —mask "**/*.{ts,tsx,md,json}"`
- `qmd embed`로 임베딩 생성, `qmd update`로 갱신. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
3. `~/.claude/mcp.json`에 qmd MCP 서버 추가해서 Claude Code가 qmd의 `search, vsearch, query, get` 등을 쓸 수 있게 함. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
4. 프로젝트의 `CLAUDE.md`(또는 글로벌 `~/.claude/CLAUDE.md`)에 “파일 읽기 전에 항상 qmd를 먼저 사용하라”는 규칙을 명시해서 Claude가 기본적으로 qmd를 우선 사용하도록 유도. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
### qmd 검색 모드
- `search`: BM25 키워드 검색, 가장 빠르고 보통 80%의 케이스에서 사용 권장. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- `vsearch`: 임베딩 기반 유사도 검색, 정확한 키워드를 몰라도 개념적으로 가까운 코드를 찾을 때 사용. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)
- `query`: 키워드+벡터 혼합에 LLM 리랭킹까지 하는 고품질 모드, 복잡한 질문에 사용. [medium](https://medium.com/@simonsruggi/youre-using-claude-code-wrong-here-s-how-to-save-95-of-tokens-db6114c1f4d6)

# Tech Stack & Constraints

# Functional Requirements (핵심 로직 검증용)
## 1. 인증 (Simple Auth)
- JWT 기반 간이 인증: 회원가입(닉네임+비밀번호), 로그인, 토큰 발급/검증.
- 인증된 사용자만 글 작성·수정·삭제·좋아요·댓글(대댓글) 가능.
- 본인이 작성한 글과 댓글만 수정·삭제 가능 (권한 체크 필수).
## 2. 게시글 CRUD (Markdown & OG Tag)
- 게시글 저장 시 백엔드에서 Python 라이브러리(BeautifulSoup4 등)를 사용해 본문 내 첫 번째 URL의 Open Graph(이미지, 제목)를 크롤링하여 DB에 별도 컬럼으로 저장. (AI의 백엔드 처리 능력 테스트)
- 작성 시 Markdown 포맷 지원 (react-markdown + rehype-sanitize 적용하여 XSS 방지 필수, 필요하다면 오픈소스 에디터 사용 가능).
- 본문에 URL 입력 시 자동으로 Open Graph 메타데이터를 가져와 '카드 형태'로 미리보기 표시.
## 3. 반응형 인터랙션
- '좋아요' 기능은 Optimistic UI(낙관적 업데이트)로 구현하여 즉각적인 반응성 확보. 사용자당 1회 제한(토글 방식).
- 조회수 카운팅 (중복 조회 방지 로직 포함).
## 4. 무한 대댓글 (Recursive Comment)
- SQLite와 SQLAlchemy에서 'Adjacency List' 패턴을 사용하여 계층형 댓글 구조(부모-자식)를 설계하고, 이를 중첩된 UI로 렌더링.
## 5. 검색
- 제목 + 본문 풀텍스트 검색. SQLite FTS5 활용 권장.
- 검색 결과에서 매칭 키워드 하이라이트 표시.
## 6. 리스트 및 정렬
- 최신순, 좋아요순, 조회수순 정렬 탭.
- 페이지네이션 대신 '무한 스크롤' 혹은 '더 보기' 버튼 구현.
## 7. 관리자 모드 (Admin Board Management)

- 관리자 대시보드에서 게시판(Board)을 무한 생성할 수 있는 기능 구현: 게시판 이름·설명·슬러그를 입력하면 즉시 새 게시판이 생성되고, 각 게시판은 독립적인 게시글 목록을 가짐.
- 게시판 목록 조회·수정·삭제(Soft Delete) CRUD 완비.
- 일반 사용자는 생성된 게시판 목록을 사이드바 또는 탭으로 탐색 가능.
- Seed Data에 기본 게시판 2~3개(예: '자유게시판', 'Q&A', '공지사항')를 자동 생성할 것.

1. SEO 필수 전략
1.1 기술 SEO(Technical SEO)
적절한 메타 태그
<title>, <meta name="description">에 명확한 키워드 포함.[web:1][web:6]
각 페이지마다 유니크한 타이틀/디스크립션 구성.[web:6]
의미론적 HTML 구조
시맨틱 태그 사용: <header>, <main>, <article>, <section>, <nav>, <footer>.[web:1][web:4]
헤딩 계층 구조: 페이지당 <h1> 1개, 이후 <h2> ~ <h4>로 논리적 계층 형성.[web:1]
URL 구조
짧고, 의미 있는 슬러그 사용: /post/123 대신 /blog/web-seo-guide.[web:12]
소문자, 하이픈 기준, 불필요한 파라미터 최소화.[web:12]
사이트맵 및 인덱싱
sitemap.xml, robots.txt 제공 후 Search Console 등록.[web:6]
Canonical 태그로 중복 콘텐츠 정리.[web:6]
1.2 콘텐츠 SEO(On-page)
키워드 전략
메인 키워드 + 롱테일 키워드 조합으로 제목, 본문, 서브헤딩에 자연스럽게 사용.[web:3][web:12]
내부 링크 구조
관련 글/페이지 간 내부 링크로 크롤링 경로 최적화.[web:1][web:5]
스니펫/리치 결과
FAQ, 리뷰, 제품 등 Schema.org 구조화 데이터 적용.[web:6]
1.3 성능 기반 SEO (Core Web Vitals)
주요 지표
LCP(Largest Contentful Paint): 2.5초 내.[web:24]
CLS(Cumulative Layout Shift): 0.1 이하.[web:24]
INP(Interaction to Next Paint): 200ms 내.[web:19][web:33]
관리 전략
Lighthouse, PageSpeed Insights, Search Console Core Web Vitals 리포트 주기적 확인.[web:24][web:37]
2. 로딩 속도 최적화 전략
2.1 자원 최적화
번들 사이즈 감소
JS/CSS Minify 및 Tree Shaking, 사용하지 않는 코드 제거.[web:4][web:14]
코드 스플리팅(라우트 기반, 컴포넌트 지연 로딩) 적용.[web:9][web:14]
이미지 최적화
WebP/AVIF 포맷 사용, 적절한 해상도 제공(Responsive Images, srcset/sizes).[web:7][web:14]
Lazy Loading(loading="lazy", IntersectionObserver).[web:4][web:7]
압축 및 전송
gzip/Brotli 압축 활성화.[web:7][web:14]
HTTP/2, HTTP/3(QUIC) 사용으로 다중 전송 최적화.[web:39]
2.2 렌더링 최적화
CSS/JS 로딩 전략
크리티컬 CSS 인라인, 나머지는 지연 로딩.[web:4][web:14]
JS는 defer/async로 파서 블록 최소화.[web:1][web:7]
폰트 최적화
Web Font Preload, font-display: swap 적용.[web:4][web:14]
초기 렌더링 전략
SSR/SSG 도입으로 최초 페인트 가속.[web:14][web:36]
3. 캐싱 전략
3.1 브라우저/HTTP 캐싱
Cache-Control
정적 자산: Cache-Control: public, max-age=31536000, immutable.[web:15]
HTML 문서: no-cache 또는 짧은 max-age + ETag.[web:15]
ETag/Last-Modified
조건부 요청(304 Not Modified)로 네트워크 트래픽 절감.[web:15]
3.2 CDN 캐싱
글로벌 CDN 사용
Cloudflare, Akamai, Fastly, Vercel CDN 등으로 엣지 캐싱.[web:7][web:39]
캐시 무효화 전략
파일명 해시로 캐시 우회(app.abc123.js).[web:15]
3.3 서비스 워커 & PWA 캐시
기본 전략 패턴[web:8][web:15]
Cache First: 정적 리소스(아이콘, 폰트).
Network First: 최신성이 중요한 API 데이터.
Stale-While-Revalidate: UX와 신선도 균형 필요 영역.
오프라인 지원
기본 셸 + 최근 페이지/데이터 오프라인 동작.[web:17][web:22]

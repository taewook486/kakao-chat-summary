## Claude Sonnet 4.6 소개 (2026년 2월 17일) ([Anthropic][1])
**Claude Sonnet 4.6**은 지금까지 나온 Sonnet 모델 중 가장 뛰어난 모델입니다. 코딩, 컴퓨터 사용, 긴 문맥 추론(장문 맥락 추론), 에이전트 계획(자율 계획), 지식 작업, 디자인 전반에서 능력이 **전면 업그레이드**되었습니다. 또한 **100만(1M) 토큰 컨텍스트 창(베타)**를 제공합니다. ([Anthropic][1])
Free/Pro 플랜 사용자는 이제 **claude.ai**와 **Claude Cowork**에서 기본 모델이 Sonnet 4.6으로 바뀝니다. 가격은 Sonnet 4.5와 동일하며, **백만 토큰당 입력 $3 / 출력 $15부터** 시작합니다. ([Anthropic][1])
Sonnet 4.6은 더 많은 사용자에게 **개선된 코딩 역량**을 제공합니다. 일관성, 지시 준수(Instruction following) 등이 좋아져, 사전 접근(early access) 개발자들은 이전 버전보다 Sonnet 4.6을 훨씬 더 선호했습니다. 종종 2025년 11월의 최고급 모델인 **Claude Opus 4.5**보다도 더 선호했다고 합니다. ([Anthropic][1])
이전에는 Opus급 모델이 필요했던 성능—현실의 경제적 가치가 큰 **사무(office) 작업**까지 포함—이 이제 Sonnet 4.6으로 가능해졌다고 말합니다. 또한 기존 Sonnet 모델들에 비해 **컴퓨터 사용 능력**도 크게 향상됐다고 합니다. ([Anthropic][1])
새 Claude 모델마다 하듯이, Anthropic은 Sonnet 4.6에 대해 **광범위한 안전성 평가**를 수행했습니다. 그 결과는 최근 Claude 모델들과 비교해 **동등하거나 더 안전**하다는 것이었습니다. 안전 연구진은 Sonnet 4.6이 “전반적으로 따뜻하고, 정직하며, 친사회적이고, 때때로 유머도 있는 성격을 보이며, 안전 행동이 매우 강하고, 고위험 형태의 정렬 실패(고위험 미스얼라인먼트)에 대한 큰 우려 신호가 없다”고 결론 내렸다고 합니다. ([Anthropic][1])
## 컴퓨터 사용(Computer use) ([Anthropic][1])
대부분의 조직에는 **쉽게 자동화할 수 없는 소프트웨어**가 있습니다. 현대적 인터페이스(API 같은 것) 이전에 만들어진 특수 시스템과 도구들 때문입니다. 과거에는 AI가 그런 소프트웨어를 쓰게 하려면 맞춤형 연결 도구(커넥터)를 따로 만들어야 했습니다. 하지만 사람이 컴퓨터를 쓰는 방식 그대로 컴퓨터를 사용할 수 있는 모델은 이 판을 바꿉니다. ([Anthropic][1])
Anthropic은 2024년 10월에 **범용 컴퓨터-사용 모델**을 처음 소개했다고 말합니다. 당시에는 “아직 실험적이고, 번거롭고, 오류가 나기 쉽다”고 했지만 빠른 개선을 기대했습니다. AI의 컴퓨터 사용을 평가하는 대표 벤치마크인 **OSWorld**는 모델이 얼마나 발전했는지 보여준다고 설명합니다. OSWorld는 시뮬레이션된 컴퓨터에서 Chrome, LibreOffice, VS Code 등 실제 소프트웨어로 수행하는 수백 개 과제를 포함합니다. 특별한 API나 전용 커넥터 없이, 모델은 사람이 하듯이 (가상) 마우스를 클릭하고 (가상) 키보드로 입력합니다. ([Anthropic][1])
16개월 동안 Sonnet 계열은 OSWorld에서 꾸준히 점수가 올랐고, 벤치마크 밖에서도 개선이 보인다고 합니다. 초기 사용자들은 복잡한 스프레드시트를 탐색하거나 여러 단계의 웹 폼을 채운 뒤, 여러 브라우저 탭을 오가며 마무리하는 작업에서 **인간 수준 능력**을 보고 있다고 합니다. ([Anthropic][1])
물론 모델은 여전히 가장 숙련된 인간 사용자보다는 컴퓨터 사용이 뒤처집니다. 하지만 개선 속도는 매우 인상적이며, 컴퓨터 사용이 더 많은 업무에서 실용적이 되었고, 더 강력한 모델도 손에 닿는 거리에 있다는 뜻이라고 말합니다. ([Anthropic][1])
한편, 컴퓨터 사용에는 위험도 있습니다. 악의적 행위자는 웹사이트에 지시문을 숨겨 모델을 가로채는 **프롬프트 인젝션(prompt injection) 공격**을 시도할 수 있습니다. Anthropic은 이에 대한 저항성을 높여 왔고, 안전성 평가 결과 Sonnet 4.6은 Sonnet 4.5 대비 **크게 개선**되었으며 Opus 4.6과 **유사한 수준**이라고 합니다. 완화 방법은 API 문서에 더 있다고 안내합니다. ([Anthropic][1])
## Claude Sonnet 4.6 평가(Evaluating) ([Anthropic][1])
컴퓨터 사용 외에도 Sonnet 4.6은 전반적인 벤치마크에서 개선됐다고 합니다. 가격 대비 **Opus급 지능에 근접**하며, 더 많은 작업에 실용적이라고 주장합니다. 기능과 안전 관련 행동은 시스템 카드(system card)에 자세히 설명되어 있고, 아래에는 요약 비교가 있다고 합니다. ([Anthropic][1])
Claude Code에서의 초기 테스트에서, 사용자들은 Sonnet 4.6을 Sonnet 4.5보다 **약 70%** 더 선호했습니다. 코드 수정 전에 문맥을 더 잘 읽고, 같은 로직을 복제하기보다는 공유 로직을 통합(consolidate)해 장시간 작업에서 덜 답답했다고 보고했습니다. ([Anthropic][1])
또한 사용자들은 Sonnet 4.6을 2025년 11월의 Opus 4.5보다도 **59%** 더 선호했습니다. Sonnet 4.6이 과도한 설계(overengineering)나 “게으름(laziness)”이 덜하고, 지시 준수가 의미 있게 더 좋다고 평가했습니다. 성공했다고 거짓 주장하는 경우가 줄고, 환각(없는 사실을 지어내는 것)이 줄며, 여러 단계 작업에서 끝까지 수행하는 일관성이 좋아졌다고 합니다. ([Anthropic][1])
Sonnet 4.6의 **100만 토큰 컨텍스트**는 전체 코드베이스, 긴 계약서, 수십 편 논문을 한 번의 요청에 담기에 충분하다고 합니다. 더 중요한 점은, 그 많은 맥락 전체에 걸쳐 **효과적으로 추론**한다는 주장입니다. 이 점이 장기 계획(long-horizon planning)에 도움이 된다고 말합니다. ([Anthropic][1])
이 부분은 특히 **Vending-Bench Arena** 평가에서 분명히 나타났다고 합니다. 이 평가는 모델이 시간에 걸쳐 (시뮬레이션된) 사업을 운영하는 능력을 보고, 여러 AI 모델이 경쟁해 더 큰 이익을 내는 방식입니다. Sonnet 4.6은 새로운 전략을 보였는데, 처음 10개월 동안 생산/운영 능력(capacity)에 크게 투자해 경쟁자보다 훨씬 더 많이 지출한 뒤, 마지막 구간에서 수익성에 집중하도록 급격히 전환(pivot)했습니다. 이 전환 시점이 좋아서 경쟁에서 크게 앞섰다고 합니다. ([Anthropic][1])
초기 고객들은 전반적 개선을 보고했고, 특히 프론트엔드 코드와 재무 분석이 두드러졌다고 합니다. 또 Sonnet 4.6의 시각적 출력은 이전 모델보다 레이아웃, 애니메이션, 디자인 감각이 더 세련됐다고 독립적으로 평가했으며, 실서비스 수준 결과에 도달하기까지 반복 수정 라운드가 줄었다고 합니다. ([Anthropic][1])
## 제품 업데이트(Product updates) ([Anthropic][1])
Claude Developer Platform에서 Sonnet 4.6은 **적응형 사고(adaptive thinking)**와 **확장 사고(extended thinking)**를 지원하고, **컨텍스트 압축(context compaction, 베타)**도 제공합니다. 이는 대화가 한도에 다가가면 오래된 맥락을 자동 요약해 “실질적으로 쓸 수 있는 문맥 길이”를 늘리는 기능이라고 설명합니다. ([Anthropic][1])
API에서는 웹 검색(web search)·가져오기(fetch) 도구가 검색 결과를 걸러내고 처리하는 코드를 자동으로 작성·실행해, 관련 내용만 컨텍스트에 남기도록 개선했다고 말합니다(품질과 토큰 효율 향상). 또한 코드 실행, 메모리, 프로그램적 도구 호출, 도구 검색, 도구 사용 예시가 “일반 제공(Generally available)” 상태가 되었다고 합니다. ([Anthropic][1])
Sonnet 4.6은 확장 사고를 꺼도, 어떤 사고 노력(thinking effort)에서도 강한 성능을 낸다고 주장합니다. Sonnet 4.5에서 마이그레이션하는 경우, 속도와 신뢰성의 균형점을 찾기 위해 설정 스펙트럼 전반을 실험해보라고 권합니다. ([Anthropic][1])
또한 Anthropic은 **가장 깊은 추론이 필요한 작업**(예: 코드베이스 리팩터링, 다중 에이전트 워크플로우 조정, “정확히 맞아야 하는” 문제)에서는 여전히 **Opus 4.6**이 최강 옵션이라고 말합니다. ([Anthropic][1])
Claude in Excel 사용자의 경우, 애드인이 **MCP 커넥터**를 지원해 S&P Global, LSEG, Daloopa, PitchBook, Moody’s, FactSet 등 외부 도구와 연결할 수 있다고 합니다. 엑셀을 떠나지 않고도 스프레드시트 밖의 맥락을 끌어올 수 있으며, claude.ai에서 MCP 커넥터를 이미 설정했다면 Excel에서도 자동으로 같은 연결이 동작한다고 합니다. Pro/Max/Team/Enterprise 플랜에서 제공된다고 합니다. ([Anthropic][1])
## 사용 방법(How to use) ([Anthropic][1])
Claude Sonnet 4.6은 모든 Claude 플랜, Claude Cowork, Claude Code, API, 주요 클라우드 플랫폼에서 사용 가능하다고 합니다. 무료 티어도 기본을 Sonnet 4.6으로 올렸고, 파일 생성, 커넥터, 스킬, 컨팩션(압축)도 포함된다고 말합니다. ([Anthropic][1])
개발자는 Claude API에서 **`claude-sonnet-4-6`** 모델명을 사용해 빠르게 시작할 수 있다고 안내합니다. ([Anthropic][1])
## 각주(사용자가 붙인 것 중 핵심만) ([Anthropic][1])
* OSWorld는 통제된 환경에서 특정 컴퓨터 과제를 테스트합니다. 유용한 지표지만 현실의 컴퓨터 사용 전체를 대표하진 못합니다. 현실은 더 지저분하고 모호하며, 실수 비용도 더 큽니다. 어떤 벤치마크도 그걸 완전히 담아내진 못했다고 합니다. ([Anthropic][1])
* 기타 벤치마크(예: Terminal-Bench 2.0, SWE-bench Verified 등)는 실행 설정·샘플링·평가 방식 같은 조건을 함께 공개합니다(세부 조건은 원문 각주 참고). ([Anthropic][1])
### 모순/누락 체크(짧게)
* 사용자가 붙여넣은 내용에 “**Sonnet 4.6은 1M 컨텍스트**”라고 나오지만, 동시에 “**컨텍스트 압축은 50k에서 트리거**” 같은 각주 언급도 보입니다. 둘은 충돌이 아니라 **기능 층위가 다름**입니다.
* 1M은 “한 번에 넣을 수 있는 입력 창” 쪽이고,
* 컨텍스트 압축은 “대화가 길어질 때 예전 내용을 요약해 실효 길이를 늘리는 운영 기능”입니다. ([Anthropic][1])
원문을 “완전한 직역(문장별)”로도 재구성해줄 수 있는데, 지금 번역은 읽기 좋게 문단 단위로 매끈하게 다듬은 버전입니다.

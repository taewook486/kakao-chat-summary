### 💬 주요 토픽 & 논의 (Q&A 제외한 논의만)

**[OCR 모델 비교 및 성능 논의]**
- GLM-OCR(0.9B)이 OmniDocBench 기준 94.62%로 SOTA 수준이며, 가격이 매우 저렴하고 텍스트/표/그래프 인식이 우수하다는 의견이 지배적임.
- PaddleOCR-VL-1.5(0.9B)도 94.5%로 성능이 우수하며 실세계 시나리오와 다국어 지원(111개 언어)에서 강점을 보임.
- Qwen3-VL(7B)은 OCRBench 등에서 상위권이며 범용성이 좋지만, GLM-OCR보다는 문서 파싱 전문성은 떨어질 수 있음.
- DeepSeek-OCR(3B)은 저VRAM 환경에서 효율적이며 빠르지만 범용성 면에서는 다소 떨어진다는 평가.
- **결론:** 복잡한 문서 파싱에는 GLM-OCR이나 PaddleOCR-VL 추천, 범용적 용도에는 Qwen3-VL 추천.

**[개발 도구: Claude Code vs Oh My OpenCode vs GLM-5]**
- **Claude Code(Codex):** "클로드 공장"이라 불릴 정도로 에이전트 워크플로우(시지푸스, 헤파이토스 등)와 내부 최적화가 잘 되어 있음. 토큰 효율과 속도가 뛰어나지만 사용량 제한이 있음.
- **Oh My OpenCode(OMO):** 클로드 코드의 UI/UX를 가져오면서 다양한 LLM(GLM-5, 오퍼스 등)을 연동할 수 있는 장점. 다만 사용자가 프롬프트를 잘 다뤄야 하며 스킬 설정에 익숙해져야 함.
- **GLM-5:** 코딩 성능이 코덱스 5.3 수준으로 평가받으며 가성비가 매우 좋음. Ollama Cloud를 통해 무료로 클로드 코드와 연동하여 사용 가능(`ollama launch claude --model glm-5:cloud`).
- **비교:** 코덱스의 '사기' 같은 편의성과 OMO의 확장성 중 선택의 기로. 현업에서는 코덱스의 안정성을 높이 평가하면서도 GLM-5와 같은 저렴한 모델을 섞어 쓰는 방식(짭클로드)이 인기.

**[하드웨어 및 로컬 LLM 환경]**
- **Mac Studio:** 통합 메모리(Unified Memory)의 편의성이 있지만 대역폭(M4 Ultra ~1000GB/s)이 RTX 5090(~1792GB/s)보다 낮아 대규모 연산에서는 속도 저하가 있을 수 있음.
- **DGX Spark:** 273GB/s 대역폭, 통합 메모리 구조지만 H100(3.35TB/s)이나 RTX 5090 대비 추론 속도가 느린 편. 개인용 개발보다는 휴대성에 초점.
- **RTX 5090 vs H100:** RTX 5090의 대역폭이 매우 높아 개인용 고성능 추론에 유리하며, H100은 데이터센터용으로 압도적인 성능을 보임.
- **권장:** 파인튜닝이 주 목적이면 엔비디아(GPU), 가성비와 다양한 테스트가 목적이면 맥(Mac) 추천.

**[지식 관리 및 오토메이션 (Molto, Langent, MCP)]**
- **Molto 봇:** 카카오톡 대화 내용 분석 및 요약 등 자동화된 업무를 수행. 주기적인 학습과 지침 충돌 해결이 중요.
- **Langent:** 로컬 문서 폴더를 3D 지식 맵(네뷸라)으로 시각화하고 벡터 DB(ChromaDB)와 그래프 DB(Neo4j)를 결합한 RAG 프레임워크. MCP 서버로 동작하여 클로드 등에 연결 가능.
- **MCP(Model Context Protocol):** 로컬 도구(스크립트, DB 등)를 클로드 코드나 오픈코드에 연결하여 컨텍스트를 확장하는 핵심 기술로 부상.

**[스캔 및 문서 처리 워크플로우]**
- **비파괴 스캐너:** Cezar Aura Pro(중고 10~15만원), vFlat 앱(거치대/스탠드 활용) 등을 이용한 책 스캔 방법론 공유.
- **절단기:** 물리적 파괴 스캔(컷터)이 속도는 압도적으로 빠르지만 책 손상 문제 존재.
- **OCR 자동화:** vFlat 등으로 스캔 후 GLM-OCR 등을 통해 텍스트화하여 RAG로 활용하는 흐름이 일반적.

**[환경영향평가(EIA) 자동화의 현실적 어려움]**
- 환경영향평가 보고서는 수치의 정확성이 법적 책임으로 이어질 수 있기 때문에, 현재 AI OCR의 할루시네이션 위험으로 인해 완전 자동화는 위험하다는 공감대 형성.
- AI는 초안 작업 및 보조 용도로만 활용하고, 최종 검수는 반드시 인간이 수행해야 한다는 결론.

### 💡 꿀팁 및 도구 추천 (구체적 실용 정보만)
- **Claude Code/Omo 단축키:** 모드 변경(Ex. Medium -> High)은 `Ctrl+T` 입력 후 선택 가능.
- **GLM-5 무료 사용:** Ollama Cloud 이용 시 터미널에서 `ollama serve` 후 `ollama run glm-5:cloud` 또는 `ollama launch claude --model glm-5:cloud` 명령어로 클로드 코드 인터페이스와 연동 가능.
- **OCR 앙상블 기법:** `doclayout-yolo`로 레이아웃 분석 후 텍스트 부분만 잘라서 Light On OCR2, PaddleOCR VL, Qwen3 VL 등 여러 모델로 돌리고 결과를 비교/검토.
- **비파괴 스캔 효율화:** 스마트폰 거치대(프로기 등) + vFlat 앱 + 발스위치(foot switch) 조합으로 손을 쓰지 않고 빠르게 촬영 가능.
- **스킬 추천:** Oh My OpenCode 사용 시 `everything` 스킬(검증 및 테스트 자동화), `superpower` 스킬(설계 및 기능 구현)이 유용함.
- **구독 해지 팁:** GPT Pro 등 구독형 서비스는 환불 기간 내라면 바로 캔슬(Stop Subscription) 신청 시 즉시 해지되며 크레딧이 반환됨.
- **Mac Studio 구매 팁:** 로컬 LLM 돌릴 시 RAM 용량이 중요하므로 256GB 이상 권장(비용 상 96GB나 128GB도 고려 대상).

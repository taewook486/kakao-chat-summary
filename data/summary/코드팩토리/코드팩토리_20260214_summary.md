- **[코딩 툴 비교 (Claude Code vs Codex vs Cursor)]**
  - **Claude Code (CC):** 오픈소스 생태계(Superpowers, OMC 등 스킬)가 강력하여 이동이 어려움. 병렬 세션 작업 시 Git 충돌 처리나 워크플로우 자동화가 뛰어남. 제어하지 않으면 엉뚱한 곳을 건드릴 수 있어 스킬/프롬프트 관리가 필요.
  - **Codex:** 단순한 작업에는 잘 따르지만 복잡한 작업에는 CC가 더 나을 수 있음. 스킬/플러그인/팀 기능 등이 부족하여 커스터마이징 자원 소모가 큼. 브랜치를 자동으로 파주나 병합 시 스트레스가 있을 수 있음.
  - **공통:** CLI 사용이 가능하며, 'Oh My OpenCode'와 같은 플러그인을 통해 연동하여 사용하는 사례 소개.
- **[카카오톡 챗지피티 프로 이슈]**
  - 이벤트 시작 직후 대량 구매(사재기)로 인해 판매가 조기 종료됨.
  - 카카오 공식 답변: 1인당 5개 구매 제한 정책 명확히 적용, 초과 등록분은 취소 및 환불 진행. 93일 이내 등록 필요, 등록 후 순차대기열 사용 가능.
  - 사재기 및 리셀링으로 인한 유입 저하와 손해 논란.
- **[구글 및 앤티그래비티 밴(Ban) 이슈]**
  - 최근 구글이 프록시 사용을 약관 위반으로 간주하여 계정을 밴하기 시작함.
  - API로 연결하지 않은 타사 연결(클로드, 오피스 등)도 약관 위반 가능성이 있어 주의 필요.
  - OpenClaw나 Antigravity에서 Auth 계정으로 사용 시 밴 사례 다수 발생(특히 프록시 사용 시). 본 계정은 살아있으나 부계정들이 밴당되는 케이스 공유.
- **[멀티 에이전트 및 토론 기법]**
  - 여러 모델(Claude, Gemini, Codex 등) 간의 토론을 유도하여 아이디어를 도출하거나 검증하는 시도.
  - Alfie: 역할과 최대 턴수를 정확히 정하지 않으면 결론이 허술해지거나 산으로 갈 수 있어 추천하지 않음. 오히려 사용자가 확실한 방향을 제어하는 것이 나음.
  - Jordy: 클로드의 팀 에이전트 기능을 활용하여 병렬 아이디어 도출 및 3라운드 토론으로 보고서 작성 성공.

### 💡 꿀팁 및 도구 추천 (구체적 실용 정보만)
- **오마이오픈코드(Oh My OpenCode):**
  - 여러 CLI(Claude, Codex)를 연결하여 플러그인과 스킬을 활용할 수 있는 통합 툴.
  - Github: `https://github.com/Yeachan-Heo/oh-my-claudecode` (Codex, Gemini CLI 지원 업데이트됨).
- **클로드 코드 팁 및 명령어:**
  - `/handoff`: 현재 세션의 컨텍스트를 정리하여 클립보드에 복사해주는 커스텀 스킬(수동 clear 후 붙여넣기 용도). Github: `https://github.com/quantsquirrel/claude-handoff-baton`
  - `/insights`: 사용 패턴을 정량적으로 분석하고 개선할 스킬/훅 등을 추천해주는 명령어.
  - `pre-compact hook`: 컴팩트 전에 실행되는 훅을 이용하여 세션 시작 과정을 자동화할 수 있음(티먹스 또는 OMC 활용).
  - `/clean`: 코드 정리 기능을 하는 스킬(상담하는 죠르디 언급).
- **멀티 에이전트/토론 도구:**
  - `pal-mcp-server`: CLI를 호출하여 여러 구독 모델 간 토론을 시킬 수 있는 MCP 서버. Github: `https://github.com/BeehiveInnovations/pal-mcp-server`
  - `claude-synod-debate`: 클로드 코드 내에서 토론을 시키는 스킬/도구. Github: `https://github.com/quantsquirrel/claude-synod-debate`
  - `b-pillar-research-report`: 토론/연구 리포트 생성 예시. Github: `https://github.com/quantsquirrel/b-pillar-research-report`
- **클로드 코드 스킬 관리:**
  - 프로젝트별로 스킬을 관리하거나, 심볼릭 링크(symlink)를 걸어 공유하는 방식 제안.
  - 규칙 생성이나 `claude.md` 스킬 작성을 통해 일관성 있는 결과물 얻기 편집자P 추천.
- **생산성 및 마인드셋:**
  - "뭐가 효율적일까?" 같은 질문은 생산성을 떨어뜨리므로 금지. 긍정적인 질문을 던지는 것이 뇌의 작동에 좋음.
  - 바이브코딩을 할 때도 사용자가 명확한 주도권을 쥐고 제어해야 하며, AI에게 과도하게 의존하면 토큰만 낭비됨.
- **기술 스택 추천:**
  - 데이터베이스/백엔드: Firebase, Supabase(진입 장벽 낮음), AWS(장벽 높음 but 장기적 답).
  - 언어: Python(R과 함께 통계용으로 추천), Rust(장점 많음), Go(언급됨).
